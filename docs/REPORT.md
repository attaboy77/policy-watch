# 뉴스 id(make_id) 수정 보고 — 2026-11-20

## 요약

- **문제**: 뉴스 id를 만드는 `make_id()`가 URL의 `?` 뒤를 통째로 버렸다. 기사번호가
  쿼리에 있는 사이트(`articleView.html?idxno=…`, `news_read.php?uid=…`)는 **사이트의 모든
  기사가 같은 id**가 됐고, "정확 일치 중복 제거"에서 한 건만 남고 나머지가 사라졌다.
  10/29 이후 **32건**이 이렇게 잘못 빠졌다(조세일보 감리지적사례 연재 6건 등, 아래 §4).
- **원인 범위**: 공식 소스는 같은 버그(법제처 18건→1건)를 `make_id_exact()`로 이미 고쳤다.
  뉴스(`google_news.py`, `naver_news.py`)만 남아 있었다.
- **수정**: 추적 파라미터만 버리고 **나머지 쿼리는 전부 남기는 블랙리스트 방식**.
  파라미터 순서가 달라도 같은 id가 나오게 정렬한다.
- **기존 id 영향**: 남는 파라미터가 없는 URL(쿼리 없음·추적 파라미터만 있음·구글 뉴스)은
  **예전과 id가 같다**. 바뀌는 것은 기사번호 등 쿼리가 있는 네이버 수집 기사뿐이다.
- **마이그레이션**: sent_log 13건, first_seen 26건을 새 id로 옮겼다. 다음 실행에서 이미
  보낸 기사가 "신규"로 다시 나가는 건 **0건**(시뮬레이션 확인, 마이그레이션 없었다면 2건).
- **오피스텔 기사 개별 제외**: 이제 두 일간NTN 기사의 id가 달라서 한 건만 뺐다.

## 1. 바뀐 규칙

`sources/_utils.py` `make_id()`:

1. URL 소문자화, 앞뒤 공백 제거, `#` 이후(프래그먼트) 제거 — 예전과 같음
2. 쿼리 파라미터 중 **추적 파라미터만 버림**
3. 남은 파라미터를 이름·값 순으로 **정렬**해 붙임(순서 무관)
4. 남은 파라미터가 없으면 `?` 없이 — 예전 id와 동일

버리는 추적 파라미터(`TRACKING_PARAM_PREFIXES`, `TRACKING_PARAMS`):

| 종류 | 이름 |
|---|---|
| 접두어 | `utm_*` |
| 광고·SNS 클릭 | `fbclid`, `gclid`, `igshid`, `dclid`, `gbraid`, `wbraid`, `msclkid`, `yclid` |
| 메일·분석 | `mc_cid`, `mc_eid`, `_ga`, `_gl` |
| 구글 뉴스 | `oc` |

**`oc`를 넣은 이유**: 구글 뉴스 RSS 링크는 `…/rss/articles/<기사키>?oc=5` 꼴이다. 기사 키는
경로에 있고 `oc=5`는 출력 옵션이다. 남기면 구글 뉴스 항목 **전부**의 id가 바뀌어 AI 요약
캐시(`summary_cache.json`)·구글 링크 디코딩 캐시·전일 캐시 대조를 잃는다. 넣어서 구글 뉴스
id는 하나도 안 바뀐다(테스트 고정).

**일부러 남긴 것**: `?ref=naver`, `?sc=Naver`, `?OutUrl=naver`, `?inflow=N`, `?cooper=NAVER`
같은 매체별 유입 표시는 지시대로 버리지 않았다(블랙리스트에 없는 건 전부 남김). 같은 기사가
네이버로 매일 같은 URL로 오므로 id는 안정적이다. 혹시 같은 기사가 유입 표시만 다른 URL로
들어와도 dedupe가 **제목 일치**로도 묶으므로 중복 노출 위험은 낮다. 나중에 이것들을
블랙리스트에 추가하면 그 사이트 id가 다시 바뀌므로 그때도 이번처럼 마이그레이션이 필요하다.

9~10월 기사가 새 id로 다시 수집돼도 메일로 나가지 않는다.
