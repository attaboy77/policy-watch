## [2] 점수 구성

```python
# sources/_utils.py:347-353
def recency_score(published, today=None):
    d = ((today or date.today()) - published).days
    return max(0, 100 - d * 6)

def final_score(trust, kw, rec):
    return round(trust * 0.55 + kw * 0.30 + rec * 0.15, 2)
```

| 항목 | 가중치 | 원점수 | 점수 기여 |
|---|---|---|---|
| 신뢰도 `trust_score` (매체 등급, `_config.py:552` `TRUST_TIERS`) | **0.55** | tier1 100 / tier2 80 / tier3 70 / tier4 50 / 기타 20 | 55 / 44 / 38.5 / 27.5 / 11 |
| 키워드 `keyword_score` (`_utils.py:160`) | **0.30** | 필수 키워드 1개당 20 + 조합 키워드 1개당 10, 최대 100 | 20→6, 30→9, 40→12 |
| 최신성 `recency_score` | **0.15** | `100 − 경과일×6`, 하한 0 | 오늘 15, 3일 12.3, 10일 6, 16일 0.6, **17일 이후 0** |

- **발행일은 반영된다. 가중치는 0.15이고 최대 15점이다.** 하루에 0.9점씩 줄어 17일째에 0이 된다.
  그 뒤로는 발행일이 점수에 전혀 영향을 주지 않는다. 17일 된 기사와 8개월 된 기사가 같은 점수다.
- 이웃한 등급 사이의 신뢰도 차이(tier2→tier4 16.5점, tier1→tier2 11점, tier3→tier4 11점)는 최신성 최대치와 비슷하거나 더 크다.
  그래서 실제 순위는 **등급 → 키워드 → (17일 이내일 때만) 발행일** 순서로 정해진다.
- 점수는 수집 시점에 매겨져 `final_score`로 저장된다. 같은 기사라도 날마다 최신성이 줄어든다(예: "제동" 11/24 49.7 → 11/25 48.8).
- 발행일 하한은 점수와 별도로 두 개가 있다. 언론 1년 상한(`NEWS_MAX_AGE_DAYS = 365`, 전 뉴스)과 네이버 수집 단계 90일 창이다.
  **구글 뉴스 경로에는 90일 창이 없다**(아래 [4]).

### 매일 바뀌는 구조적 이유

1. **구글 뉴스 경로에 코드 쪽 날짜 창이 없다.** `google_news.fetch_category()`(`sources/google_news.py:147`)는 검색어의 `when:90d`에만 의존한다.
   그런데 구글은 이를 지키지 않는다. 오늘 ESG 98건 중 72건이 90일 초과다.
   네이버(`sources/naver_news.py:99`)는 90일 밖이면 `collect:out_of_window`로 뺀다. 그래서 오래된 기사는 사실상 구글 경로로만 들어오고, 1년 상한까지 남는다.
2. **구글 응답 표본이 날마다 다르다.** 검색어가 같아도 돌려주는 기사 수(45→98)와 구성이 바뀐다.
3. **점수가 등급 위주라, 옛 tier2 기사 수가 그대로 자리 수를 정한다.** ESG 전문지(ESG경제·임팩트온)는 tier2(80)다.
   그 옛 기사들은 모두 53.0점(키워드 30) 또는 56.0점(키워드 40)으로 같아서, 구글이 그날 몇 건 주느냐가 곧 상위 몇 자리를 차지하느냐가 된다.
   최근 기사(대부분 네이버 경로, tier4·기타)는 남는 자리만 받는다.
4. **동점이 많다.** 오늘 53.0점이 14건이다. 상한 정렬은 동점이면 입력 순서를 유지한다.
   오늘은 16위가 51.5점이라 동점 안에서 잘린 건이 없었지만, 53.0점 기사가 한 건만 더 왔어도 동점 중 무엇이 빠질지는 수집 순서가 정했을 것이다.
